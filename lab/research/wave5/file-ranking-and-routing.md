# Wave 5 — File-Ranking Gaps, Query-Type Routing, and Sub-Document PRF: 2024–2026 Training-Free Literature Scan

Scoped to two measured gaps plus one re-scan: **(1) FILE ranking** — roust File@10 82.7 vs trained SweRankEmbed 90.9; the multi-channel engine earns only +3pp FILE over bare BM25 (the sole significant ablation delta); E-class misses (gold file never returned) are 80% lexically visible on Lite (only 60.1% on Verified, per E7b), i.e. ranking losses, not vocabulary gaps — with chronic hub-file attractors (`sympy/core/expr.py`, `sphinx/application.py`) winning on incidental generic-term overlap. **(2) Query-type effects** — E17 measured code-block-bearing queries at 30.9% gold-line capture vs 56.3% for traceback queries; the repro snippet's tokens hijack bag-of-words ranking toward test/example-shaped code; E11 (query-type routing) was designed, never built. **(3)** Wave-2 declared region-level pseudo-relevance feedback published-literature-free — re-scanned here through Aug 2026.

Deliberately not re-covered: RRF/Condorcet/Borda/TA-NRA and conformal fusion gating (`wave1/rank-aggregation.md`, `arxiv-ir-theory-2026-07.md`), call-graph PageRank and SBFL (`wave1/fault-localization.md`), Leiden/heat-kernel/resistance centrality (`arxiv-se-networks-2026-07.md`), granularity/packing-objective/stopping results (`wave2/*`). All experiments proposed below inherit the wave-4 discipline: gate on **both** Lite-300 and Verified-406, FILE=277/300 invariant.

## (a) Closing the lexical-vs-trained FILE gap

### a1. LexBoost — corpus-graph neighbor score smoothing, training-free at inference **[HTML/abs]** — best E-class fit found

Kulkarni, Goharian, Frieder, MacAvaney, "LexBoost: Improving Lexical Document Retrieval with Nearest Neighbors," ACM DocEng 2024, arXiv:2409.05882.

**Numbers first.** Final score = `λ·BM25(q,d) + (1−λ)·mean_{n∈N(d)} BM25(q,n)` over an offline corpus graph (16 nearest neighbors per doc). At λ=0.7, all statistically significant (p<0.05): TREC DL19 MAP .3877→.4150, R@1000 .7555→.7922; DL20 MAP .3609→.3862, R@1000 .8046→.8241; TREC-COVID MAP .2525→.2950 (~+17%). Robust across BM25/PL2/DPH/QLD as the base scorer. No neural re-ranker anywhere in the query path.

- **Mechanism for roust**: a gold file with weak direct overlap gets promoted because its neighbors score well — the exact E-class shape ("gold file never returned despite terms being visible"). roust has a graph substrate dense-IR papers lack: the import graph, plus a BM25-kNN file graph computable at index time. One λ, one neighbor count. Hub caution: hub files also have many neighbors — the paper's *mean* (not sum) aggregation is load-bearing, and a high-degree-node exclusion is a cheap extra guard (hub files are precisely high-degree in any similarity graph).
- **Caveat**: the paper builds its graph with dense encoders (TCT-ColBERT-HNP/TAS-B) offline. But GAR (a2) and Quam both report BM25-built graphs matching or beating dense graphs — the fully model-free variant (BM25-kNN or import-edge graph) is plausible and specifically **unmeasured**: that combination is roust's experiment to run, not a published number to cite.
- **Transferability verdict**: **direct, low effort** — a score-blend at file-ranking time over a graph built at index time; fits the existing flag-gated harness loop.

### a2. GAR lineage — adaptive candidate expansion via corpus graph **[HTML/abs]**

MacAvaney, Tonellotto, Macdonald, "Adaptive Re-Ranking with a Corpus Graph," CIKM 2022, arXiv:2208.08942 (pre-2024, root of the requested lineage). Alternates between scoring the initial BM25 pool and the graph neighbors of the best-scored-so-far docs — documents with zero initial-pool presence get pulled in via similarity to documents that were returned. Up to +8% nDCG on MS MARCO; the corpus graph is BM25-kNN (deterministic, offline). Successors are all neural-scorer-dependent, flagged not omitted: Quam (WSDM 2025, arXiv:2410.20286 — trained affinity model; R@1000 DL19 .755→.867 — but its BM25-built graphs matched dense graphs, independent evidence for the lexical substrate), SlideGAR (ECIR 2025, arXiv:2501.09186, LLM listwise ranker), ORE (SIGIR 2025, arXiv:2504.09353).

- **Mechanism for roust**: GAR's gains require a stage-2 scorer stronger than stage-1 (monoT5 in the paper). roust's analog: bare BM25 as stage 1, the full multi-channel score as stage 2 over the expanded pool. Whether +3pp-over-BM25 channels are strong enough to make traversal pay is exactly the open question — but this is the only mechanism in this scan that can rescue files with literally zero initial-pool presence, which is the E-class definition.
- **Transferability verdict**: **transplant, medium effort**, second-line behind a1 (a1 is the one-parameter static version of the same cluster-hypothesis bet; escalate to GAR-style traversal only if a1 gates positive).

### a3. BMX — entropy-weighted BM25 extension **[HTML/abs]**

Li, Lipp, Shakir, Huang, Li (Mixedbread AI), arXiv:2408.06643, 2024. Adds (i) per-query-token normalized Shannon entropy across containing documents into the TF saturation, and (ii) an additive lexical token-overlap term `β·E(qᵢ)·S(Q,D)`, `S = |Q∩D|/m`. Core BMX is deterministic; the optional WQA query augmentation needs GPT-4 (flagged, separable). Measured: BEIR avg nDCG@10 40.36→41.52 (+1.16); LoCo 89.98→90.12 (negligible).

- **Mechanism for roust**: the entropy term explicitly down-weights tokens that appear indiscriminately across many documents — the precise channel hub files exploit (E7b: `core/expr.py` wins on 2–3 generic terms like "simplify"/"subs" that appear in dozens of files). Port the entropy weighting **without** the `|Q∩D|` overlap term — that term favors large vocabulary-diverse files, i.e. would feed the hub-attractor failure rather than damp it.
- **Transferability verdict**: **transplant, low effort, modest expected gain** (+1pp-class in its own tables) — worth a flag-gated sweep as a hub-damping term, not as a headline fix.

### a4. Chunk-max file scoring — segmentation (BRTracer) + AST chunking (cAST) as hub-file defense **[PDF + HTML/abs]**

Wong, Xiong, Zhang, Hao, Zhang, Mei, "Boosting Bug-Report-Oriented Fault Localization with Segmentation and Stack-Trace Analysis," ICSME 2014 **[PDF]**: split each file into equal segments (l=800 words), file score = **max segment similarity**. Segmentation-alone ablation (their Table VIII, vs BugLocator baseline): Eclipse MAP 27.5→29.4, SWT MAP 41.5→44.2 — deterministic, measured, and explicitly motivated as killing large-file noise. Zhang, Zhao, Wang, Yang, Wei, Wu (CMU), "cAST: Enhancing Code Retrieval-Augmented Generation with Structural Chunking," Findings of EMNLP 2025, arXiv:2506.15655, is the modern code-native version: recursive AST split-and-merge under a size budget (tree-sitter, deterministic); +4.3 Recall@5 on RepoEval retrieval, +2.67 Pass@1 SWE-bench (retriever in their experiments likely embedding-based — verify before citing the deltas as lexical).

- **Mechanism for roust**: score AST chunks, aggregate to file via max (or top-k-mean) chunk score instead of whole-file accumulation. A 4,000-line hub file becomes many chunks each competing on its own length-normalized merits; scattered incidental overlap no longer accumulates into one giant document score, while a gold file with one dense on-topic region keeps its peak. This is the same intervention family as the adopted pad-lines/len-exp win, moved up one level to the FILE stage — and it composes with a1 rather than competing.
- **Transferability verdict**: **transplant, low–medium effort** — roust already parses with tree-sitter and scores regions; the change is which aggregate the FILE ranker consumes. BRTracer supplies the deterministic measured precedent; cAST supplies the code-native chunking recipe.

### a5. Fusion, genuinely new only: convex combination beats RRF; weak channels actively hurt **[HTML/abs]**

Bruch, Gai, Ingber, "An Analysis of Fusion Functions for Hybrid Retrieval," ACM TOIS 42(1), 2023, arXiv:2210.11934 (2023, but the definitive instance, not previously covered): a tuned convex combination of min-max-normalized scores outperforms RRF in-domain and out-of-domain; RRF is sensitive to its k; the normalization choice is largely immaterial; CC weight tuning is sample-efficient (a handful of queries suffices). Wang et al., "Balancing the Blend," arXiv:2508.01405 (2025, cs.DB): large experimental study of sparse/dense/FTS fusion — a weak component **substantially degrades** fused accuracy ("weakest link"); recommends path-wise quality assessment before fusing. (Adjacent, **[snippet]** only, noted not load-bearing: arXiv:2603.28886 reports percentile-rank normalization mattering more than the fusion rule.)

- **Mechanism for roust**: the +3pp-over-BM25 channel attribution is consistent with the weakest-link result — indiscriminately fused low-signal channels dragging the blend toward BM25. Two deterministic moves: (i) if any channel pair is RRF-fused, replace with one tuned λ over min-max-normalized scores; (ii) per-query channel gating — drop a channel from the blend when its own top-score distribution is flat (a QPP-lite check, cheaper than the conformal machinery wave-1 already catalogued).
- **Transferability verdict**: **direct, low effort**; the CC-over-RRF claim is TOIS-reviewed and the tuning burden is one scalar on the existing 300-instance harness.

### a6. Negative findings (a-thread), stated plainly

- **No 2024–2026 lexical paper directly fixes long/hub-document bias.** The classic length-normalization line (BM25L/BM25+) fixes the *opposite* problem (long docs over-penalized) and would make hub attraction worse. The only literature handle is **retrievability bias** (Azzopardi & Vickers, CIKM 2008; measurement-only 2025 successor T-Retrievability, arXiv:2508.21704): hub files have pathologically high retrieval frequency across unrelated pseudo-queries *by construction* — a per-file retrievability prior computed offline is a deterministic corpus-statistics intervention, but **no paper reports it as a ranking fix with measured gains**; it would be novel engineering, flagged as such (same status wave-2 gave within-file RM3).
- **Deterministic document expansion is a dead thread in 2024–2026.** The active doc-expansion literature is entirely neural (Doc2Query++, SPLADE-v3, DyVo). Nothing post-RM3 and model-free with measured gains was found; roust's shipped identifier-splitting + doc-level RM3 already sits at the deterministic frontier here. Effort belongs in a1/a4, not here.

## (b) Query-type-conditional retrieval (E11's literature)

### b1. BLIZZARD — the definitive deterministic router **[PDF]**

Rahman & Roy, "Improving IR-Based Bug Localization with Context-Aware Query Reformulation," ESEC/FSE 2018, DOI 10.1145/3236024.3236065.

**Numbers first.** 5,139 bug reports, 6 Java systems; deterministic regex classification into BR_ST (16.1%), BR_PE (53.8%), BR_NL (30.1%). Per-class treatment, all training-free: **ST** → discard trace lines as text, build a trace graph (nodes = class/method per frame; edges intra-tuple + caller–callee between adjacent frames), PageRank (d=0.85), query = exception name + error message + top-11 terms. **PE** → two text graphs (co-occurrence window K=2; POS-dependency), PageRank, query = **top-30 terms only, rest of the report dropped**. **NL** → PRF over top-10 Lucene results, append top-8 source-term-graph terms. Results (baseline→BLIZZARD): **BR_ST Hit@10 48.25→75.21, MAP@10 28.09→45.50**; BR_PE Hit@10 72.09→77.84, MAP 47.28→52.08; BR_NL Hit@10 61.23→65.21. Overall Hit@10 66.47→74.52; ~25% of queries worsened (not risk-free).

- **Mechanism for roust**: the class asymmetry mirrors E17's measured gap in sign — untreated baselines bleed worst on structured-noise queries, and the fix is **replacement, not reweighting**: the structured block is mined for a few graph-selected terms and then discarded as bulk text. For the code-block class (BLIZZARD's PE, its smallest gain, +5.7 Hit@10) the honest read is: term *selection* helps but is not the whole cure — which motivates pairing with a document-side prior (b4).
- **Transferability verdict**: **direct transplant, medium effort** — regex classifier + per-class term extraction in the query pipeline; the trace-graph PageRank reuses machinery roust's symbol-graph work already has. The 2024–2026 deterministic lane is empty (see b5), so this 2018 recipe is still the state of the deterministic art.

### b2. BRTracer — trace-frame file boosting, deterministic, with a clean trace-only ablation **[PDF]**

Same paper as a4 (ICSME 2014). Trace handling: regex-extract file names from frames, validate against the codebase → set D (directly named) plus C (files imported by D); **BoostScore = 1/rank for D-files in the top-10 frames, 0.1 for deeper D-files and for C-files**; final = normalized segment-VSM + boost. (Top-10-frames rule from Schröter et al., MSR 2010.) **Trace-boost-alone ablation**: AspectJ MRR 35.1→44.2 (+9.1pts), MAP 19.8→25.2; Eclipse MAP 27.5→29.4; SWT MAP 41.5→44.2. Lobster (Moreno et al., ICSME 2014, DOI 10.1109/ICSME.2014.37, abstract-verified via OpenAlex; body paywalled) corroborates with a dependency-graph trace-proximity score fused with Lucene: improves-or-maintains in 82% of 155 trace-bearing cases.

- **Mechanism for roust**: the traceback class is roust's *best* class (56.3%) under bag-of-words — a rank-decayed additive file boost for frame-named files plus a 0.1 spillover to their import neighbors is a ~50-line deterministic change that pushes the best class further and is a natural component of the E11 routing package rather than a separate experiment.
- **Transferability verdict**: **direct, low effort**; the measured trace-only delta (+3–9 MRR pts over bag-of-words) is the cleanest published answer to "what is trace-aware handling worth."

### b3. Part-selection over issue structure: Chaparro (EMSE 2019) + Mills (ICSME 2018) **[abs + PDF]**

Chaparro, Florez, Marcus, "Using bug descriptions to reformulate queries during text-retrieval-based bug localization," EMSE 24:2947–3007 (2019), DOI 10.1007/s10664-018-9672-z: querying with title+observed-behavior instead of the full report retrieves buggy code in top-N for **+25.6% more queries** on average; title+OB+S2R/EB variants **+31.4–41.7%**, consistent across engines. (Their part labels were manual/trained — for GitHub issues, markdown fences and trace regexes give the labels deterministically, which makes the transplant *easier* than the original setting.) Mills, Pantiuchina, Parra, Bavota, Haiduc, "Are Bug Reports Enough for Text Retrieval-based Bug Localization?", ICSME 2018 **[PDF]**: with near-optimal term selection over only the report's own vocabulary, localization succeeds in most cases **even with all code-ish hint terms removed** — Q_all vs Q_noHint not statistically different under oracle selection.

- **Mechanism for roust**: Mills is the theoretical license for E11 — 30.9% capture on snippet queries is a **selection failure, not an information deficit** (matching the project's own measured 0.93 lexical ceiling). Chaparro is the measured payoff for structure-aware part selection. Together: parse the issue into {prose, code-fence, traceback} channels; score prose as today; mine fences/traces for identifiers then drop them as bulk text.
- **Transferability verdict**: **direct, low–medium effort**; the SWE-bench issue format is self-delimiting, so the deterministic version of Chaparro's manual labeling is nearly free.

### b4. Document-side prior: test/production distinction **[repo/abs]**

Kim & Lee, "Are datasets for IR-based bug localization techniques trustworthy?", EMSE 26(3), 2021 (artifact: github.com/RosePasta/BugTypeBasedIRBL): re-benchmarks six classic IRBL tools under production-only vs test-only localization and shows the split materially shifts accuracy. Their classifier is Naive Bayes, but a path-rule version (`test/`, `tests/`, `examples/`, `docs/`) is trivially deterministic.

- **Mechanism for roust**: the E17 diagnosis is that repro-snippet tokens make the query *look like test code*, so test/example files win. A conditional prior — downweight test/example-shaped paths **only when the query's code-fence channel dominates its term mass** — attacks exactly that interaction, and only fires on the measured-bad class (bounded blast radius, the lesson from the `w_name` regression).
- **Transferability verdict**: **direct, low effort** as a component of the E11 package; gate for regressions on instances whose gold files genuinely are tests.

### b5. Ceilings and the empty lane **[HTML/abs]**

Trained/LLM references, for calibration only: **IQLoc** (Samir & Rahman, arXiv:2510.04468, JSS 237:112860, 2026) — hybrid IR+transformer query reduction; +118.70% MAP on stack-trace reports, +111.87% code-element, +127.45% NL-only (its per-type ordering — ST easiest, code-element middle, NL hardest — matches E17's sign even with an LLM in the loop). **BRaIn** (arXiv:2501.10542) — LLM relevance feedback, +87.6% MAP margins on Bench4BL. **Reformulate-Retrieve-Localize** (Caumartin & Melo, arXiv:2512.07022, 2025) — LLM extracts identifiers from the issue *before* BM25, ~35% better first-file ranking vs raw-issue BM25: direct 2025 evidence that pre-BM25 reformulation, not a better ranker, closes much of the gap — and its reformulation output (identifier extraction) is exactly what a regex parser produces deterministically. Confirmed from the Agentless paper text: Agentless prompts with the **original issue description** and embeds the **original issue description** — no stripping or special handling of code blocks anywhere; SweRank names verbose issue queries as its motivating problem but fixes it with contrastive training. **Nobody in the SWE-bench localization line does deterministic structure-aware query parsing — E11 is unoccupied ground.**

## (c) Sub-document PRF: is wave-2's "unclaimed" verdict still true?

**Verdict: survives, but must be narrowed.** As of Aug 2026, sub-document units as feedback *source* are published — including one deterministic SIGIR 2026 instance — but **no published method, deterministic or otherwise, uses top-scoring spans of a document as a local relevance model to re-rank other spans of the same document** (source AND target sub-document, inside one file). Wave-2's claim should be restated in that narrower form wherever it is load-bearing.

### c1. PLAID-PRF — the paper that narrows the claim **[HTML/abs]**

Wang, MacAvaney, Macdonald, "PLAID-PRF: Pseudo-Relevance Feedback with Centroid-like Tokens in PLAID," SIGIR 2026, arXiv:2607.18626. Deterministic, training-free (reuses the frozen index's centroids): selects diverse high-utility **token-level** centroid vectors from top results and appends them to the query's token vectors. Up to +4.3% nDCG@10 / +7.3% MRR@10 over PLAID on MS MARCO + 4 BEIR sets. Dense multi-vector space; feedback drawn corpus-wide; target is corpus re-ranking — not lexical, not within-file. Cite and differentiate; do not claim "no deterministic sub-document PRF exists" anymore.

### c2. PRM — the strongest deterministic precedent for position-weighted feedback **[PDF]**

Lv & Zhai, "Positional Relevance Model for Pseudo-Relevance Feedback," SIGIR 2010, DOI 10.1145/1835449.1835546. Expansion terms weighted by **proximity to query-term occurrences inside feedback documents** via a Gaussian kernel positional LM (`exp(−(i−j)²/2σ²)`, soft passages). Measured: Terabyte06 MAP NoFB .3047 / RM3 .3131 / **PRM1 .3322** (+9.0% over NoFB vs RM3's +2.8%); ClueWeb09-B eMAP .0713/.0755/**.0809**; PRM1 beats hard-passage RM3-p (.3322 vs .3077) — soft positional weighting ≥ explicit passage segmentation; needs only 10 expansion terms vs RM3's 70; robust at σ≈200, λ≈0.1; works even with a single feedback document.

- **Mechanism for roust**: PRM is the deterministic ancestor of "trust the region of the file where the query matched." The within-file transplant is PRM's mechanism pointed at a new target: use terms Gaussian-near the top-scoring lines of an already-selected file as a local relevance model to re-score *other candidate lines in the same file* (D-class: right file, wrong function — still the largest fixable pool, 27.8pp Lite / 33.0pp Verified per E7b). PRM improves the expansion model for corpus re-ranking and never re-scores positions within the document as output — that last step is the unclaimed piece.
- **Transferability verdict**: **exploratory, not a transplant** — same status wave-2 assigned, now with a stronger citable ancestor (PRM's +6–13% over RM3, training-free, 10 terms) and a mandatory differentiation from PLAID-PRF. No 2024–2026 revival of the positional lever exists (the EACL 2026 feedback survey, arXiv:2508.15437, lists no within-document positional feedback work) — the neural mainstream abandoned it, which is favorable ground for a lexical engine.

### c3. LLM-era analogs, ceilings only **[HTML/abs]**

BRaIn (arXiv:2501.10542; +87.6% MAP margins on Bench4BL, file-level feedback) and CSQE (Lei et al., EACL 2024, arXiv:2402.18031; LLM extracts pivotal *sentences* from BM25's top-k for expansion — DL19 nDCG@10 50.6→67.3, BEIR 6-set 43.7→49.7) both validate the headroom of feedback-driven reformulation; both use an LLM as the span/doc relevance oracle. A deterministic span-relevance oracle — roust's own line scorer — is exactly the substitution the within-file experiment would test. LLM-Assisted PRF (Otero & Parapar, ECIR 2026, arXiv:2601.11238) — LLM-gated RM3, same story.

### c4. Deterministic loops on SWE-bench: graph expansion exists, term feedback does not **[HTML/abs]**

LARGER (Hu, Su, Zhao, Zhu, Haque, arXiv:2605.16352, 2026): lexical anchors into an AST-derived repo graph, confidence-filtered k-hop expansion — deterministic, training-free, no embeddings in the expansion step. Reported (HTML, summarizer-extracted, treat as approximate): LocBench Acc@5 BM25 49.3 / Agentless 68.9 / **LARGER 87.0**. Expansion signal is structural edges, not first-round terms — explicitly not PRF, complementary to roust and corroborating a1/a2's graph bet from the code side. Beyond it, every iterative SWE-bench localization loop found is LLM-driven (CoSIL, SWE-Debate arXiv:2507.23348, Explorative IRBL arXiv:2508.00253, BRaIn): **no published system deterministically feeds round-1 retrieved code terms back as round-2 expansion on SWE-bench** — roust's shipped doc-level RM3 already occupies that spot, unpublished.

## Caveats
