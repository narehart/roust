*Companion to `lab/research/wave5/fresh-sota-scan.md` (June–Aug 2026 SOTA scan; do not re-tread), `lab/research/wave4/e7b-post-adoption-autopsy.md`, and `lab/research/wave4/e17-postadoption-case-mining.md` (branch `wave4-mining`, commit `e02cd5b`). Question, per campaign #4's two post-adoption boundaries: (a) language-agnostic function/block boundary detection without per-language engineering, and (b) set-valued ("sweep") edit-site localization — given one high-confidence site, deterministically find its siblings. Literature gathered 2026-08 via web-research subagents; all citations verified against primary sources except where flagged in Caveats.*

## The two boundaries, measured (internal grounding)

**LANGUAGE.** From `lab/results_regions/agentless_metric_mswe_jsts.json` + `mswe_jsts_adopted.jsonl` (580 Multi-SWE JS/TS instances, adopted engine `92baeeb`): FILE 46.38, LINE all-or-nothing 9.31, mean fraction covered .1805 (median .0). **FRAGMENTATION.** From E17: 11/30 top-D-mass cases have no majority owner; 22/30 spread across ≥4 owner functions; `sympy-13878`'s gold patch touches 18 sibling distribution constructors. And from E16 (branch `e16-sibling`, commit `1a105af`): the naive same-class sibling *density* boost was **REJECTED** — 38.7/24.3 (w=0.25) and 36.7/23.0 (w=0.75) vs baseline 53.3/42.7, monotone dose-response, Verified arms cancelled. # Part (a) — Multi-language block detection without per-language engineering

## a1. Field consensus: every shipping system uses tree-sitter CST walking; nothing else has measured accuracy

| System | Citation | Mechanism for non-Python boundaries | Numbers |
|---|---|---|---|
| cAST | arXiv:2506.15655 (Zhang et al., 2025) | tree-sitter parse → split-then-merge: keep node whole if under budget, recursively split oversized, greedily merge small adjacent siblings; size in non-whitespace chars | vs fixed-line chunking: RepoEval Recall@5 **+4.3** (75.0 vs 70.7, GIST), CrossCodeEval EM +4.3, SWE-bench Pass@1 +2.7 |
| SweRank+ | arXiv:2512.20482 (Reddy et al., Salesforce) | "Tree-sitter parsing tool is employed to extract all functions" — **one mechanism, uniformly, for all 10 languages** (JS/Java/TS/Ruby/Rust/Go/PHP/C/C++/Py) | Function Acc@10 62.39 retriever-only / 71.37 reranked on SWE-Bench-Multilingual |
| Multi-SWE-bench's MagentLess | arXiv:2504.02605 (Zan et al., ByteDance) | "We implemented function and class extraction for all languages using Tree-sitter"; but **punted on non-Python skeletons** ("extracting file skeletons is challenging in some programming languages") and fell back to whole-file content | Error analysis: "a significant number of failures… due to incorrect fault localization" |
| Aider repo-map | aider.chat/2023/10/22/repomap.html | tree-sitter + **vendored modified `tags.scm`** per language; graph-ranked defs/refs under a token budget | ~50 languages with tags support out of 168 recognized |
| Sweep AI chunker | github.com/sweepai/sweep, docs blog | tree-sitter CST, greedy child-bundling to 1,500 chars, recursive split; 12 languages; fallback = 40-line windows w/ 15 overlap, **hit 0.1% of traffic** | adopted by LlamaIndex CodeSplitter (verified in source) |
| Continue.dev | core/indexing/chunk/code.ts (verified in source) | web-tree-sitter (WASM); oversized class/fn nodes collapse to signature + `{ ... }` | — |
| GitHub code nav | docs.github.com | tree-sitter, 21 languages | — |
| ast-grep / difftastic | ast-grep.github.io; difftastic repo | 33 langs in-binary (ast-grep; extras as dylibs); ~44 grammars **vendored as generated C** (difftastic) | difftastic binary: 114 MB uncompressed (measured, aarch64-darwin 0.70.0) — the bundle-everything ceiling |

Two directly-on-point conclusions. First, the two research systems closest to roust's task (cAST for chunking-for-retrieval, SweRank+ for multi-language function-level localization) both treat "tree-sitter extract function boundaries" as a solved subroutine, and cAST is the only *quantified* comparison of structural vs heuristic chunking anywhere — structure wins +4.3 Recall@5. Second, Multi-SWE-bench's own authors, with tree-sitter in hand, found the non-Python *representation* problem hard enough to punt to whole files — and then named localization their top failure cause. The region-packing gap roust hit on JS/TS is the same gap the benchmark's authors hit.

## a2. tags.scm vs node-type allowlist

tree-sitter's code-navigation system (tree-sitter.github.io/tree-sitter/4-code-navigation.html) standardizes `@definition.function/.method/.class` captures in per-grammar `queries/tags.scm` files — but the standardization is **aspirational**: per-repo maintainers write them at "varying sophistication levels," not every grammar ships one, and aider vendors *modified* copies rather than trusting upstream. The alternative that most chunkers (Sweep, Continue, LlamaIndex, cAST) actually use: skip queries, walk the CST with a ~10-entry per-language allowlist of node types (`function_declaration`, `method_definition`, `arrow_function`, `class_declaration`, …). That is ~10 lines of config per language, not per-language *engineering* — and it is the only approach that handles JS/TS's expression-level functions (`const f = () => {…}`, object-literal methods), which defeat any Python-style header-regex port (see a4).

**Transferability**: direct. `python_blocks()` (core.rs:2202) already emits exactly the right output shape — nested multi-granularity `(start, end)` spans with preamble. A `ts_blocks(text, lang) -> Vec<(usize, usize)>` walking a tree-sitter CST for allowlisted node types, emitting the same class-span + member-span nesting, slots into the single branch at core.rs:2545. The greedy packer, padding, length-norm, and anchor seating all apply unchanged.

## a3. Cost/benefit of tree-sitter in a single-binary Rust tool

- **Source cost (measured from grammar repos)**: generated `parser.c` — JavaScript 2.72 MB, TypeScript 8.34 MB + TSX 8.36 MB, Java 2.44 MB, Go 1.50 MB, Python 3.29 MB, C++ 24.66 MB. JS+TS+TSX ≈ 19.4 MB of C source.
- **Binary cost**: table-driven C compresses well into .text/.rodata; estimated ~1–4 MB per common grammar compiled (estimate, not published — see Caveats). The measured worst case is difftastic: ~44 vendored grammars → 114 MB binary. Bundling 3–5 grammars is a small fraction of that; single-digit-MB growth for the JS/TS family is the reasonable expectation.
- **Build mechanics**: each grammar compiles via the `cc` crate at build time; zero runtime deps; needs only a C compiler (C++ toolchain for a few scanners).
- **The real cost is version churn, and it is well documented**: tree-sitter core 0.21 broke all grammar crates pinned below it (tree-sitter/tree-sitter#3095); ABI 15 (0.25.x) broke again (zed#24632); some grammars aren't on crates.io or lag the core version (difftastic#891 catalogs the ecosystem symptoms). The mitigation every serious consumer converged on: **vendor the generated `parser.c` pinned to one core version** (difftastic) or pin a curated pack (aider). For roust: vendor js/ts/tsx pinned, treat grammar updates like any other gated dependency bump.
- **Rejected variants**: WASM (`web-tree-sitter`, Continue's choice) needs a wasm runtime — wrong for a single binary; ast-grep-style dynamic libraries break single-binary distribution; GitHub's stack-graphs (arXiv:2211.01224) is name-*resolution* (overkill for boundaries), required hand-written per-language rule files, and the repo is now **archived/unmaintained** (verified via API) — a clear negative signal against anything fancier than plain CST walking.

## a4. Heuristic alternatives: an honest null

- **universal-ctags** (docs.ctags.io): 142 hand-written C parsers + 31 regex "optlib" parsers (~170 languages, counted from the repo tree); `--fields=+ne` does emit function end lines, but end-support varies by parser and **no formal accuracy study of ctags boundaries exists** (searched; none found). It is also an external binary and is per-language logic — someone else's, not less of it. Main value to roust: a cheap *oracle* for evaluating our own boundary detector, not a component.
- **Indentation/brace heuristics**: no paper measures the accuracy of column-0-brace ("defun convention") or pure-indentation function detection — editor folklore, unquantified. The legitimizing literature exists — island grammars (Moonen, WCRE 2001, DOI 10.1109/WCRE.2001.957806: parse "islands" of interest, "water" for the rest) and lightweight lexical extraction (Murphy & Notkin, TOSEM 5(3) 1996, DOI 10.1145/234426.234441) — but both are frameworks that still require per-language specifications. `python_blocks` *is* a hand-rolled island parser; these papers explain why it works for Python and don't remove the per-language work for anyone else. Decisive JS/TS-specific problem: functions there are **expression-level** (arrow functions bound to `const`, object-literal methods, callbacks), so a header-regex scan structurally cannot enumerate them, no matter how good the regex.
- **String-separator chunkers** (LangChain `RecursiveCharacterTextSplitter.from_language`, verified in source): per-language separator lists (`"\nfunction "`, `"\nconst "`, …) that yield split *points* only — no end boundaries, no nesting, no names. This is the measured floor cAST beat by +4.3 Recall@5. LlamaIndex already migrated off this approach to tree-sitter.

**Verdict**: there is no credible non-parser path. The only mechanism with published multi-language wins, measured chunking gains, and a proven single-binary Rust embedding story is tree-sitter with vendored pinned grammars and a node-type allowlist.

# Part (b) — Sweep / set-valued localization: one site → sibling set

## b1. The systematic-edit family (locate-the-other-sites mechanisms)

| Item | Citation | How additional sites are found | Numbers | Transferability |
|---|---|---|---|---|
| **LASE** | Meng, Kim, McKinley, ICSE 2013 | From **≥2 example edits**: AST-diff each, abstract identifiers, extract common context (max-common-subtree over control/data-dependent unchanged statements), match that context against every method | Edit-location **precision 99% / recall 89%** on Eclipse JDT/SWT repeated fixes | The precision datapoint for the whole field. Catch: needs 2 seeds — 1 seed is exactly what Sydit showed to be under-determined. Suggests a two-pass bootstrap: seed + best sibling candidate → intersect contexts → re-scan |
| Sydit | Meng et al., PLDI 2011, DOI 10.1145/1993316.1993537 | Doesn't locate — user supplies target; abstracted dependence-context match decides *applicability* | applies 82% (46/56), 70% end-to-end correct | The context-match test is a deterministic sibling **verifier** even though it's not a finder |
| Refazer | Rolim et al., ICSE 2017, arXiv:1608.09000 | PROSE-synthesized rewrite rule; sites = matches of the rule's guard pattern over the AST | learns 84% of 56 scenarios from ~2.9 examples | PROSE machinery heavyweight; "guard = anti-unified template of seed; enumerate matches" is the transplantable skeleton |
| Getafix | Bader et al., OOPSLA 2019, DOI 10.1145/3360585 | Doesn't locate — sites come from Infer warnings; anti-unification lattice ranks fix patterns per site | top-1 human-identical fix 12–91% by category | Anti-unification = the right deterministic "similar modulo holes" primitive; site-finding delegated |
| **Blue-Pencil** | Miltner et al., OOPSLA 2019 (ships in VS IntelliCode) | Observes ≥2 edits in a session, synthesizes the transformation, **pattern-matches the rest of the document** for remaining sites | **P 0.89 / R 1.0**, 199 ms avg, 37 real sessions | Existence proof that *within-file* deterministic sweep after a seed pattern is near-perfect at interactive cost — the within-file setting is exactly roust's D-class |
| Overwatch | Zhang et al., OOPSLA 2022, arXiv:2207.12456 | Learned edit-*sequence* templates from IDE traces; prior edit predicts next site | 78% precision | Learned from proprietary traces; conceptual confirmation only |
| **Hercules** | Saha, Saha, Prasad, ICSE 2019, DOI 10.1109/ICSE.2019.00020, arXiv:1906.08903 | See b2 — the centerpiece | multi-hunk localization **63%** (15/24) vs Deckard baseline **8%**; 84% overall (129/154 Defects4J) | Highest of anything surveyed; every component deterministic |
| ITER | Ye & Monperrus, ICSE 2024, arXiv:2304.12015 | Dynamic: apply partial patch, re-run fault localization, iterate | 15.5% of 476 Defects4J 2.0 repaired | Needs test execution + neural repair; instructive contrast (dynamic re-localization vs static sibling set), not transplantable |
| SiblingRepair | arXiv:2605.06209 (2026 preprint, unrefereed) | Attacks Hercules' over-strict matcher: candidates via **token/embedding matching unconstrained by test coverage or history**, then LLM relevance filter | claims > Hercules on Defects4J/GHRB; component numbers unavailable | Signal: the 2026 frontier agrees Hercules' bottleneck is matcher *recall* — loosen toward token overlap, filter separately |
| ROSE co-change | Zimmermann et al., ICSE 2004 / TSE 31(6) 2005 | Apriori association rules over co-changed entities (incl. function-level) | fine-grained: ~15% recall, ~every-2nd-recommendation correct (secondary sources — see Caveats) | History co-change is high-precision/low-recall at entity grain: a **filter/booster**, never the finder — exactly how Hercules uses it |
| CoEdPilot | Liu et al., ISSTA 2024, arXiv:2408.01733 | Trained transformer labels line windows given prior edits | location acc 70.8–85.3% | Learned; useful only as the accuracy band a deterministic sweeper should aim at |

Base-rate justification for a sweep prior — the clone-consistency literature: **36–38% of clone genealogies change consistently as a group** (Kim, Sazawal, Notkin, Murphy, ESEC/FSE 2005, read from PDF), **~52% of clone classes contain inconsistencies** and roughly every second unintentional inconsistent change is a fault (Juergens et al., ICSE 2009, DOI 10.1109/ICSE.2009.5070547). I.e., when one clone-family member changes, the rest changing too is common — and *missing* the rest is the canonical bug source. Sweep recall is what the gold patches in E17's pool are doing right.

## b2. Hercules dissected — the mechanism that matters (read from the PDF)

Hercules defines *evolutionary siblings* of a seed repair location as locations passing two thresholds: context similarity ζ > t1 and history similarity ξ > t2. Three-step pipeline, applied lazily per suspicious statement:

1. **Statement-level AST similarity**: Zhang–Shasha tree edit distance with a custom node matcher — (a) *kind classes* (variable access ≈ array access ≈ method invocation, all "expressions"; `return` ≢ `throw`), (b) type compatibility up to subtyping, (c) **Levenshtein similarity over identifier names**, overall threshold 0.8. Identifier abstraction + name-distance is what makes `Frechet(...)` match `Dagum(...)`.
2. **Non-contiguous semantic context**: for each variable used at the seed, take its reaching-definition statement (within the method); the union is the "context of relevance," matched the same way with consistent node mappings. Their explicit motivation: **fixed-size lexical windows fail because true siblings are usually not textual clones of their surroundings** — context lives 100+ lines away. (This is the literature's version of E17's pad-reach null: 0/30 D-lines within 5 lines of a chosen span, median distance 57.)
3. **Revision-history filter/booster**: candidates whose lines historically evolved *independently* of the seed are dropped; locations that historically underwent the same AST operations are *added* even if step-1 missed them. Pure `git log`/diff analysis.

The measured payoff: generic clone detection (Deckard) localizes 8% of multi-hunk bugs; Hercules' pipeline gets 63% — **the delta between "clone detector" and "sibling finder" is steps 2–3**, not a better clone detector. Every step is available to a deterministic Rust CLI: step 1 approximable by tree-sitter-span tree-lite similarity or identifier-abstracted token bags; step 2 by "defining lines of the identifiers the seed uses" (greppable); step 3 by `git log -L` co-change — which roust's cache layer already knows how to read.

## b3. The similarity primitive and the family shortcut

- **SourcererCC** (Sajnani et al., ICSE 2016, arXiv:1512.06448): bag-of-tokens per span, clone iff overlap ≥ θ (default 0.7). BigCloneBench recall: T1 100%, **T2 97–98%**, VST3 93%, ST3 60–61%, MT3 ~5%. Implementable in a few hundred lines of Rust, no AST. The SWEEP shape (18 near-identical constructors, `_print_X` stub families) is **exactly Type-2** — rename-only clones — where recall is 97–98%. ST3 (~60%) is the known ceiling for divergent siblings; that's what Hercules steps 2–3 recover. NiCad (Roy & Cordy, ICPC 2008: pretty-print + line-LCS, best-in-class ST3 ~95% recall, second-hand) needs per-language pretty-printers — heavier than roust wants. Deckard (Jiang et al., ICSE 2007) is the measured wrong tool (8% above). CBCD (Li & Ernst, ICSE 2012) does seed→clone search via PDG isomorphism — right task, NP-complete core, wrong cost profile.
- **Family enumeration by role** — the shortcut that skips similarity entirely when the family is *nameable*: Juxta (Min et al., SOSP 2015, DOI 10.1145/2815400.2815422) got 118 real bugs by enumerating the 54 Linux filesystems implementing the same VFS entry points and cross-checking them — membership by interface role, not by clone detection. PR-Miner (Li & Zhou, ESEC/FSE 2005, DOI 10.1145/1081706.1081755) supplies the output semantics: "N−1 of N family members conform" is a confidence score for flagging the Nth. roust's D-class families are nameable *today* from `python_blocks` output alone: same method name across sibling classes in one file, shared-prefix def families (`_print_X`, `visit_X` — literally E13/E17's sympy cases), the 18 same-shape module-level constructors of `sympy-13878`.
- **Set-recall as the metric the field is converging on**: Agentless (arXiv:2407.01489, Table 2 verified) gains +5.7pp of edit-location ground-truth containment (50.67→56.33) purely by unioning 4 sampled location *sets* — sampling is their (stochastic, paid) sibling expander; a deterministic one is the training-free analogue. And arXiv:2606.11976 (2026 preprint) documents the exact roust failure mode at file level: models that maximize micro-F1 by predicting *few* locations score high precision and significantly lower **all-gold recall**. Single-pick behavior is a metric artifact the fraction/superset metrics punish; the campaign's `mean_fraction` metric is already the right objective.

# Top-3 transplants, ranked

**#1 — Vendored tree-sitter JS/TS/TSX grammars + node-type-allowlist `blocks()` replacing `window_blocks` for those extensions** (LANGUAGE boundary; the packing half of the JS/TS collapse: conditional-on-file-hit line recall median .000 vs Python's .857). Field consensus mechanism (cAST +4.3 Recall@5 quantifies structure-vs-windows; SweRank+ runs it across 10 languages; Sweep's window fallback fires on 0.1% of traffic once real languages are covered); cost is bounded and charted (≈19 MB C source for the JS family, est. single-digit-MB binary growth, `cc` build dep, pin-and-vendor to dodge documented ABI churn). Emit the same nested class/member span shape `python_blocks` already produces so the packer/padding/len-norm pipeline is untouched. **Must ship with the harness-side twin** — tree-sitter gold-function extraction for the Multi-SWE metric — or FUNCTION-level gains are literally unmeasurable (today's 99.83 is vacuous). *Effort*: medium (new dep + one function + harness plumbing); *gate*: mswe-580 JS/TS slice, FILE invariant expected (packing change only), plus the standard Lite/Verified no-regression gate (Python path byte-identical).

**#2 — Hercules-style sibling expansion from the anchored span, allocated as depth, not re-rank** (FRAGMENTATION; targets E17's 74%-precondition pool and the 11/30 no-majority-owner sweeps that no single-pick mechanism can capture). Given pass-1's highest-confidence span in a file: score other same-file candidate spans by **identifier-abstracted token-bag overlap vs the seed span** (SourcererCC ≥0.7; T2 recall 97–98% matches the sibling-constructor shape), optionally filtered by seed-identifier co-occurrence (Hercules' context-lite) and `git log -L` co-change (its history filter — roust already reads git history). Add the top 2–3 qualifying siblings as *extra* spans for that file. This is mechanistically disjoint from E16's rejected boost: E16 re-weighted the *query-density* metric for class members (and regressed monotonically); this scores **similarity-to-the-seed**, a signal the density metric doesn't contain, and adds depth instead of distorting the ranking — precisely E17's recommendation (i) plus the literature's missing ingredient. Measured ceiling math from the literature: clone-similarity alone would be Deckard-shaped (8%); it's the context/history conjunction that reached 63%. *Effort*: medium (pass-2 addition in `pack_regions`, budget-guarded like pad-lines); *gate*: expect fraction/LINE gains more than FUNCTION flips, dual Lite+Verified, watch token budget.

**#3 — Nameable-family enumeration with N−1-of-N semantics** (the cheap subset of #2 that needs no similarity engine and works today on Python). When the seed span's header matches a family definable from existing block output — same method name across sibling classes in the file, shared def-name prefix/suffix with ≥K members, same-shape module-level def family — include all members' spans (or their headers, budget permitting). Juxta proves role-membership scales as a sibling definition; PR-Miner's rule-violation framing gives the confidence semantics; Blue-Pencil proves within-file sweep-after-seed runs at P .89 / R 1.0 interactively. Handles the E17 vignette-1 pattern (`crv_types.py`, 18 constructors) that similarity thresholds might fragment. Multiplies with #1 (family enumeration on JS/TS needs #1's boundaries first). *Effort*: low-medium; *risk*: family false-positives on huge visitor classes — cap members and require the seed to be a family member, not merely class-adjacent.

**Honest nulls / not recommended**: (i) indentation/brace heuristics for JS/TS — zero measured accuracy in the literature and structurally blind to expression-level functions; porting `python_blocks`' regex approach to JS is a dead end. (ii) ctags as a component — external binary, per-language logic, unmeasured ends; keep only as an evaluation oracle. (iii) co-change history as a *finder* — ROSE's fine-grained recall ~15%; use only as Hercules-position filter/booster. (iv) stack-graphs — archived, per-language rule files, solves name-resolution not boundaries. (v) LASE-grade precision (99P/89R) requires ≥2 seeds — out of scope for pass-1 but the natural *second iteration* of #2: once one sibling is confirmed (e.g., by the agent consuming roust's output), context-intersection over two seeds is the precision upgrade path.

## Caveats

Web research ran through search/fetch subagents; each flagged its own residual uncertainty, preserved here: SweRank+ exact decimals are single-fetch; per-grammar *compiled* binary growth (~1–4 MB) is an estimate — only difftastic's 114 MB aggregate and parser.c source sizes were measured; no formal accuracy study exists for ctags or indentation heuristics (absence of evidence, stated as such); ROSE's fine-grained 15%/~50% figures come from two secondary summaries, not the TSE PDF; SourcererCC precision is reported as 86% or 97.8% under different protocols, unreconciled; NiCad's ST3 ~95% is second-hand; Juergens' "every second inconsistency is a fault" is near-verbatim via two sources but the full paper wasn't fetched; Miller & Myers user-study numbers not re-verified; Hercules publishes localization correctness, not isolated sibling-set precision/recall; SiblingRepair (2605.06209) and the exploration-structure paper (2606.11976) are unrefereed 2026 preprints; stack-graphs' EVCS 2023 venue is from memory (arXiv ID confirmed); aider's ranking being literally PageRank is community-sourced, their docs say only "graph ranking algorithm"; Cody's chunker was not investigated. Internal numbers (mswe decomposition, E16/E17 facts) were computed/read directly this session and are exact.
