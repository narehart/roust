TWO LATENT CACHE-HYGIENE BUGS, both invisible to this gate and both with ZERO
effect on the round's numbers (the harness does `git checkout -f` + `git clean
-fdq` per instance and `.roust` is not gitignored, so every instance rebuilds
the corpus cold; the manifest is only consulted on a WARM cache):

  (1) PRE-EXISTING (5ebd6ab): the manifest's `exts` pre-filter never included
      the EXT_V2 suffixes, so 0 of svelte's 2,927 .svelte files appear in the
      manifest even though the corpus indexes them. Under --ext-v2 on a warm
      cache, edits to ext-v2 files cannot invalidate the cache.

  (2) INTRODUCED by b0cf3a9: `scan_manifest` now also skips anything failing
      `core::path_indexable(rel)`, but that predicate only knows CODE and
      EXT_V2 suffixes -- it does not know DOCS_EXTENSIONS. So all 428 docs
      entries (.md 427 + .txt 1) were evicted from the manifest. The corpus
      docs channel is unaffected (identical docs_df above); only staleness
      tracking for docs files is lost.

  Suggested fix for (2): in scan_manifest, apply the fixture guard only to
  EXT_V2 admissions, e.g. keep the entry when
  `path_indexable(rel) || DOCS_EXTENSIONS.contains(suffix_of(rel))`.
  Suggested fix for (1): include EXT_V2_EXTENSIONS in the `exts` set the
  manifest scan is built from whenever ext_v2_enabled().

GENERAL LESSON: the corpus walk and the manifest scan must be filtered by the
SAME predicate, and any flag that changes corpus MEMBERSHIP must re-key the
cache. WS2c's ":cf1" is the precedent that got both right.
